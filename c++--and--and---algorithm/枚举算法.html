枚举优化 & 数位处理模板

一、 for 循环枚举终极优化指南

处理暴力搜索时，千万不要顺着题目的死脑筋去循环！

  • 最大优化（剪枝）：一个数若是分成几部分求和，那么单取某一部分绝对不会大于这个数；若多层嵌套可以持续加上几部分继续放缩。

  • 起点优化（防回头）：若有升序/不重复要求，内层循环的起点可以直接写上外层循环的变量（例如 for(b = a; ...)）。

  • 嵌套优化（降维打击）：多重嵌套时，最后一个数可以通过已知公式推导出来，从而直接砍掉最后一层循环！

  • 🔥 反向生成优化（新兵器）：当题目让你找满足 n=a×b 的 n 时，千万不要去枚举 n 然后拆因数！直接反向盲猜，外层枚举 a，内层枚举 b，算出来的 n 直接拿去过安检！效率提升百倍！

  • 🔥 全局去重优化（新兵器）：反向生成时极易产生重复的 n（比如不同的组合算出同一个合法的 n）。必须在全局开一个 bool vis[MAX] 数组，打过勾的 n 直接跳过，防止 ans 重复加钱！

【定和降维边界法】

📡 触发条件（何时使用？）

当你看到题目中同时出现以下 3 个关键字 时：

  1. 找对子：求有多少对 (a,b)。

  2. 有大小：明确规定 a<b（或 a≤b）。

  3. 有限制：知道 a 和 b 的总和 S（或者是让你枚举 S），并且知道 a,b 各自的取值范围（比如 1≤a,b≤MAX）。

🧠 纯数学推导（为什么能这么卡边界？）

假设已知两数之和为 S（即 a+b=S），且变量的绝对下限是 Lmin​，绝对上限是 Rmax​。

  • 🔪 砍上限（由 a<b 决定）：

    因为 a<b，把 b 替换成 S−a，得到 a<S−a。

    移项得到 2a<S。

    所以在整数域里，a 最大只能取到 S 的一半稍微少一点，即：

    max_a = (S - 1) / 2;

  • 🔪 卡下限（由 b 的最大值决定）：

    虽然 a 本身有绝对下限 Lmin​，但如果 a 取得太小，会导致 b 被迫变得极大！

    因为 b≤Rmax​，替换得到 S−a≤Rmax​。

    移项得到 a≥S−Rmax​。

    所以 a 必须在这两者之间取最大值兜底，即：

    min_a = max(L_min, S - R_max);
