# workflow-by-cixia — 个人工作流调度中枢

## 定位

这是 cixia 的**核心工作流技能**，承担三个职责：

1. **流程调度** — 规定开发全流程的阶段和规则
2. **技能路由** — 指导何时调用其他技能
3. **文档规范** — 定义各类文档的编写标准

---

## 二、技能路由表

| 场景 | 调用的技能 | 何时触发 |
|------|-----------|---------|
| 新需求 / 新功能 | `brainstorming` | 任何创造性工作之前 |
| 写计划文档 | `writing-plans` + 本技能的 plan-template | 需求对齐完毕后 |
| 执行计划 | `executing-plans` | 计划审批通过后，进入开发阶段时 |
| 写代码 | `test-driven-development` | 实现功能或修复 Bug 时 |
| 遇到 Bug | `systematic-debugging` | 任何测试失败 / 异常行为时 |
| 完成任务 | `verification-before-completion` | 声称"完成"之前 |
| 新开窗口 | 本技能 + 上述 6 个 | 每次会话开始时 |
| 并行多任务 | `dispatching-parallel-agents` | 有 2+ 个独立子任务时 |
| 子代理驱动开发 | `subagent-driven-development` | 大型多任务并行执行时 |
| 代码审查 | `requesting-code-review` / `receiving-code-review` | 按需手动调用 |
| 分支合并 | `finishing-a-development-branch` | 按需手动调用 |
| 隔离工作树 | `using-git-worktrees` | 需要隔离分支开发环境时 |
| 创建自定义技能 | `writing-skills` | 需要编写或修改技能文件时 |
| 浏览器自动化测试 | `browser-testing` | 需要自动化验证 UI / 浏览器行为时（Antigravity 专属） |

### 技能调用纪律

- **开局加载的 7 个技能**在每次对话开始时自动生效，不需要手动调用
- **按需调用的技能**在触发场景出现时，主动提示用户是否需要加载
- 如果有技能可能适用，**宁可多加载也不要遗漏**——加载后发现不适用可以忽略，但遗漏可能导致质量问题
- 技能之间有优先级：**流程技能先于实现技能**
  - "做一个新功能" → 先 `brainstorming`，再 `test-driven-development`
  - "修这个 Bug" → 先 `systematic-debugging`，再 `verification-before-completion`

## 三、文档规范索引

### 核心文档规范

| 文档 | 规范文件 | 何时参考 |
|------|---------|---------|
| `implementation_plan.md` | [references/plan-template.md](references/plan-template.md) | 每次创建执行计划时 |
| `HANDOFF.md` | [references/handoff-template.md](references/handoff-template.md) | 每次更新项目交接文档时 |
| 项目模块文档 | [references/module-docs-guide.md](references/module-docs-guide.md) | 首次搭建或更新项目模块文档时 |

### 文档纯净度总则

- `implementation_plan.md` → 纯净蓝图，不写对话内容
- `task.md` → 执行进度，标记 `[ ]` / `[/]` / `[x]`
- `walkthrough.md` → 完成后的变更总结
- `HANDOFF.md` → 跨会话的"外挂大脑"
- `docs/*.md` → 项目模块速查文档
