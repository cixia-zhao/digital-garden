# 桶排序与计数数组（`bkt[]`）完全指南

### 🧠 ：什么是“桶”？

想象你是一个快递分拣员，面前有一条履带（原数组 `a`），上面全是标着数字或字母的快递包裹。 传统的排序（`sort`）是让这些包裹两两比大小，谁大谁去后面，非常费脑子。 **桶计数（Bucket）的做法是：** 你直接在地上摆一排带编号的篮子（这就是数组 `bkt[]`）。

- 0 号篮子、1 号篮子、2 号篮子......
    
- 来了一个标着 `5` 的包裹，你连看都不看别人，直接把它扔进 `5` 号篮子！
    
- 来了一个标着 `B` 的包裹，你直接把它扔进标着 `B` 的篮子！
    

这就是最核心的物理映射：**包裹上的名字（数据的值），就是篮子的门牌号（数组的下标）！**

---

### 🎬 三步走：

#### 🏗️ 第一步：建场地（开辟桶数组）

**规范：** 桶的数组一定要开在 `main` 函数外面（全局变量），这样所有的篮子初始都是空的（全为 0），不需要你手动清零。 **坑点：** 桶要开多大？取决于你**包裹上的最大数字是多少**！而不是包裹有多少个。

- 如果包裹上的数字最大是 10万，桶就开 `int bkt[100005];`。
    
- 如果包裹全是英文字母（ASCII码），桶开 `int bkt[256];` 足矣！
    

#### ⚡ 第二步：全自动分拣（核心魔法代码）

这是你最需要刻在 DNA 里的代码。扔掉 `if-else`，一行代码全自动收割！

**场景 A：数字包裹查库存** 假设原数组 `a = [2, 5, 2, 1]`。



```C++
for (int i = 1; i <= n; ++i) {
    bkt[ a[i] ]++;  // 魔法发生！a[i]的值，直接变成了 bkt 的下标！
}
```

_物理真相_：来了个 `2`，`bkt[2]` 的库存加一；又来了个 `5`，`bkt[5]` 的库存加一。

**场景 B：字母包裹查库存（ASCII 魔法）** 假设字符串 `s = "BABA"`。



```C++
for (int i = 1; i <= n; ++i) {
    bkt[ s[i] ]++;  // 字母自动转成数字门牌号！
}
```

_物理真相_：C++ 底层规定了 `'A'` 是 65，`'B'` 是 66。当你写 `bkt[ s[i] ]++` 时，来了一个 `'B'`，电脑会自动把它塞进 `bkt[66]` 这个坑位里，库存加一。你完全不需要知道 66 这个数字！

#### 🖨️ 第三步：打扫战场（输出或结算）

分拣完了，怎么用呢？

**用法 1：查某人的库存（极速单查）** “老板，我想知道字母 C 出现了几次？” 代码：`cout << bkt['C'];` （一秒钟出结果，不用再去原数组里找了！）

**用法 2：顺水推舟的“天然排序”** “老板，我想把刚才的包裹从小到大排个序输出。”



```C++
// 桶的下标天生就是从小到大排列的！
for (int i = 0; i <= 100000; ++i) { // 遍历所有的篮子
    while (bkt[i] > 0) {            // 如果篮子里有货
        cout << i << " ";           // 打印篮子的门牌号
        bkt[i]--;                   // 拿走一个，直到拿空
    }
}
```

_物理真相_：因为你是从 0 号篮子一直往后翻的，所以先翻出来的数字肯定小！这直接省去了极其耗时的 `sort`，时间复杂度是极其完美的线性级别 O(N)！

### 💣 雷达预警：什么时候绝对不能用桶？

这门武功虽然天下无敌，但它有一个致命的罩门：**极其吃内存（空间）！**

- ✅ **完美场景：** 题目说“有 10 万个数，每个数的范围是 1 到 10 万”、“字符串里全是小写字母”。（数值范围小，大胆用！）
    
- ❌ **当场暴毙场景：** 题目说“有 10 个数，但这 10 个数分别是 10亿、20亿...”。
    
    - _真相_：为了这 10 个包裹，你难道要建一个大到 20 亿的超级桶数组吗？内存当场爆炸（MLE 报错）！这种时候，老老实实用回你的 `sort`！
        
- ❌ **负数陷阱：** 数组下标没有负数！如果包裹上写着 `-5`，你直接 `bkt[-5]++` 电脑会当场报错。遇到负数必须要加一个统一的“偏移量”（比如大家都加上 1000），把它变成正数再装桶。

### 负数地雷：为什么会当场暴毙？

在 C++ 里，如果你写了 `bkt[-5]++`，电脑会直接崩溃（Segmentation Fault / 数组越界访问）。 因为在电脑的物理内存里，**数组的下标只能从 0 开始**。`0` 就是一楼，电脑根本没有给你挖负数下标的“地下室”！

### 🏗️ 破解之法：空间平移大法（Offset 偏移量）

既然没有地下室，那我们就**强行把地平线往下踩**！ 假设题目告诉你，包裹上的数字范围是 **`-10000` 到 `10000`**。 最深的地下室是 `-10000` 层。

1. **定基准（找 Offset）**：我们设定一个“偏移量（Offset）”为 `10000`。
    
2. **存入（加偏移量）**：所有的包裹，进门前**统统加上这个偏移量**！
    
    - 来个包裹写着 `-10000`：加 10000，存进 `bkt[0]` 坑位。
        
    - 来个包裹写着 `-5`：加 10000，存进 `bkt[9995]` 坑位。
        
    - 来个包裹写着 `0`：加 10000，存进 `bkt[10000]` 坑位。
        
    - 来个包裹写着 `10000`：加 10000，存进 `bkt[20000]` 坑位。
        
3. **取出（减偏移量）**：当你去查库存的时候，只要**把桶的门牌号减去偏移量**，就能完美还原包裹上原本的数字！

### 模板：

```cpp
#include <bits/stdc++.h>
using namespace std;

// 1. 建立空篮子（全局变量自动为0）
// 根据题目给的【最大数值】来开大小，如果是字母开 256 即可。
int bkt[100005]; 

int main() {
    ios::sync_with_stdio(0); cin.tie(0); cout.tie(0);
    
    int n;
    if (cin >> n) {
        // 2. 无脑流水线分拣
        for (int i = 1; i <= n; ++i) {
            int val;
            cin >> val;
            bkt[val]++; // 核心魔法：把值当地址，库存 +1
        }
        
        // 3. 查库存或排序（这里演示找出现次数最多的那个数）
        int max_count = 0;
        int max_num = -1;
        
        for (int i = 0; i <= 100000; ++i) {
            if (bkt[i] > max_count) {
                max_count = bkt[i]; // 更新最大库存量
                max_num = i;        // 记住是哪个门牌号（数值）
            }
        }
        
        cout << "出现最多的数字是：" << max_num << "，出现了 " << max_count << " 次\n";
    }
    return 0;
}
```

### 负数情况

```cpp
#include <bits/stdc++.h>
using namespace std;

// 1. 设定偏移量：题目说最小负数是 -10000，那我们就把地平线拔高 10000
const int OFFSET = 10000; 

// 2. 桶的容量必须翻倍！
// 从 -10000 到 10000，总共有 200001 个数。开大一点保平安。
int bkt[200050]; 

int main() {
    ios::sync_with_stdio(0); cin.tie(0); cout.tie(0);
    
    int n;
    if (cin >> n) {
        // 【存入环节：强行拉出地下室】
        for (int i = 1; i <= n; ++i) {
            int val;
            cin >> val;
            // 核心魔法：所有数值加上 OFFSET 变成正数下标！
            bkt[val + OFFSET]++; 
        }
        
        // 【取出环节：还原本来面目】
        // 遍历整个桶（注意范围是平移后的门牌号范围）
        for (int i = 0; i <= 200000; ++i) {
            while (bkt[i] > 0) {
                // 核心还原：门牌号 i 减去 OFFSET，变回真实的数字
                int real_val = i - OFFSET; 
                cout << real_val << " ";
                bkt[i]--;
            }
        }
        cout << '\n';
    }
    return 0;
}
```

### 二维：
基础的 1D 桶排序只能当“计步器”（只记数量）；而当题目出现“双重属性”（比如：既要分门别类，又要比拼代价/重量/分数）时，我们就必须祭出这两件 2D 武器——“巨型矩阵桶（二维数组）”与“动态档案柜（Vector 数组）”！

### 🌟 为什么需要升级？（痛点场景
假设你是老板，手下有 10 个部门（编号 0-9），每个部门有若干员工，每个员工有不同的裁员代价（钱）。
 * 基础桶 cnt[部门编号]++：你只能知道 1 号部门有 5 个人。至于裁掉他们要花多少钱？对不起，这个信息被“计步器”弄丢了！
 * 升级诉求：我们不仅要把人按部门分开，还要记住每个人的代价，并且能挑出最便宜的人！
面对这个诉求，你有两大流派可以选择：
### ⚔️ 流派一：巨型矩阵桶（二维数组 cnt[x][cost]
👑 核心哲学：把“类别”和“代价”全部当成门牌号！用空间换取绝对的时间压制！
1. 基础语法与长相
// 第 1 维是部门编号 (0~9)，第 2 维是代价范围 (假设最多 20万)
int cnt[15][200005]; 

2. 实战怎么用？（纯手工，不调包）
 * 存入数据（极速）：来了一个 1 号部门的员工，裁员代价是 5000。
   cnt[1][5000]++; （翻译：1 号部门，代价为 5000 的坑位里，多了一个人）。
 * 提取最便宜的人（极速）：你想在 1 号部门挑 2 个最便宜的人裁掉。
   根本不需要 sort 排序！ 因为代价已经被你当成从小到大的门牌号了！你只需要从 0 号门牌开始挨个敲门。
```cpp
int kick_count = 2; // 需要裁 2 个人
int total_cost = 0; // 花了多少钱

// 在 1 号部门里，代价从 0 开始往上查房（天生从小到大）

for (int cost = 0; cost <= 200000; ++cost) {
    while (cnt[1][cost] > 0 && kick_count > 0) {
        total_cost += cost; // 加上这个人的代价
        cnt[1][cost]--;     // 杀掉这个人
        kick_count--;       // 目标减一
    }
    if (kick_count == 0) break; // 杀够了，收工！
}
```
3. 💣 致命雷区（什么时候绝对不能用！）
极其吃内存（MLE 暴毙警告）！
如果题目说：代价 cost 最大可以达到 10^9（十亿）。
你写下 int cnt[15][1000000000] 的那一刻，电脑内存直接爆炸。
口诀：只要第二维属性（代价/重量）的最大值超过了 10^6（一百万），立刻扔掉这个流派！
### ⚔️ 流派二：动态档案柜（Vector 数组 bkt[10]）
👑 核心哲学：门牌号只管“类别”，抽屉里塞“具体属性”！无视属性的大小，极其万能！
4. 基础语法与长相
```cpp
#include <vector>
// 开 10 个抽屉（代表 0~9 号部门）。
// 每个抽屉里挂着一个可以无限拉长的动态链表（vector）
vector<int> bkt[10]; 
```
5. 实战怎么用？
 * 存入数据（无脑塞）：来了一个 1 号部门的员工，代价是 5000（甚至是十个亿）。
```cpp
   bkt[1].push_back(5000); （翻译：拉开 1 号抽屉，把 5000 这个档案扔进去，完事！）。
   //或者
   for(int i = 1;i <= n;++i)
	{
		int a,b;cin >> a >> b;
		
		v[a].push_back(b);  //循环读入； 
	}
```
 * 提取最便宜的人（局部排序）：抽屉里的档案是乱序的，拿出来理一理。
```cpp
int kick_count = 2;
int total_cost = 0;

// 1. 把 1 号抽屉里的档案，从小到大排序
sort(bkt[1].begin(), bkt[1].end());

// 2. 拿走最前面（最便宜）的 2 份档案
for (int j = 0; j < kick_count; ++j) {
    total_cost += bkt[1][j];
}
```
3. 💣 注意事项（稍微慢一丢丢）
它需要调用 sort 函数进行排序，时间复杂度是 O(N \log N)。比上面的二维矩阵桶要稍微慢一点点，但在蓝桥杯 10^5 的数据规模下，这个速度依然是毫无压力的满分级别！
⚖️ 终极判决：考场上我该怎么选？
不要犹豫，直接套用这套条件反射选择法”**：
 * 👀 第一眼看数据范围（重点看第二属性，即代价、重量、分数）：
   * 如果代价 < 10^6：恭喜你，可以用流派一（二维矩阵桶 cnt）！代码写起来有种“降维打击”的暴力美感，速度快到飞起。
   * 如果代价极大（比如 10^9），或者你根本懒得看数据范围：无脑选择流派二（Vector 数组 bkt）！它是最坚固的防弹衣，永远不会因为内存越界报错，普适性达到 100%！
 * 建议把 vector<int> bkt[N] 作为你的第一本能！
