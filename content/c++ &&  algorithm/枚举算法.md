## 枚举优化 & 数位处理模板
### 一、 `for` 循环枚举终极优化指南

处理暴力搜索时，千万不要顺着题目的死脑筋去循环！

- **最大优化（剪枝）**：一个数若是分成几部分求和，那么单取某一部分绝对不会大于这个数；若多层嵌套可以持续加上几部分继续放缩。
    
- **起点优化（防回头）**：若有升序/不重复要求，内层循环的起点可以直接写上外层循环的变量（例如 `for(b = a; ...)`）。
    
- **嵌套优化（降维打击）**：多重嵌套时，最后一个数可以通过已知公式推导出来，从而直接砍掉最后一层循环！
    
- 🔥 **反向生成优化（新兵器）**：当题目让你找满足 $n = a \times b$ 的 $n$ 时，**千万不要去枚举 $n$ 然后拆因数**！直接反向盲猜，外层枚举 $a$，内层枚举 $b$，算出来的 $n$ 直接拿去过安检！效率提升百倍！
    
- 🔥 **全局去重优化（新兵器）**：反向生成时极易产生重复的 $n$（比如不同的组合算出同一个合法的 $n$）。必须在全局开一个 `bool vis[MAX]` 数组，打过勾的 $n$ 直接跳过，防止 `ans` 重复加钱！

#### 🧠 纯数学推导（为什么能这么卡边界？）

假设已知两数之和为 $S$（即 $a + b = S$），且变量的绝对下限是 $L_{min}$，绝对上限是 $R_{max}$。

- **🔪 砍上限（由 $a < b$ 决定）：**
    
    因为 $a < b$，把 $b$ 替换成 $S - a$，得到 $a < S - a$。
    
    移项得到 $2a < S$。
    
    所以在整数域里，$a$ 最大只能取到 $S$ 的一半稍微少一点，即：
    
    **`max_a = (S - 1) / 2;`**
    
- **🔪 卡下限（由 $b$ 的最大值决定）：**
    
    虽然 $a$ 本身有绝对下限 $L_{min}$，但如果 $a$ 取得太小，会导致 $b$ 被迫变得极大！
    
    因为 $b \le R_{max}$，替换得到 $S - a \le R_{max}$。
    
    移项得到 $a \ge S - R_{max}$。
    
    所以 $a$ 必须在这两者之间取最大值兜底，即：
    
    **`min_a = max(L_min, S - R_max);`**

### 🚀 第二阶段 单循环 + 进度条（状态机）

- **🎯 适用场景**：找“按特定顺序排列的一串子序列”（如找 2-0-2-3）。
    
- **💻 核心动作**：**绝不套娃，倒行逆施！**因为是从右往左剥，必须倒着查！
    
    
    
    ```C++

    while(x > 0) {
        int rem = x % 10;
        if(step == 0 && rem == 3)      step++; // 找 3
        else if(step == 1 && rem == 2) step++; // 找 2
        // ... 直到凑齐拉响警报
        x /= 10; 
    }
    ```
    

### 🏆 账本消消乐（多数字核对法）🔥（New!）

- **🎯 适用场景**：题目要求判断几个数字拆开后，**“出现的数字频率相同、总长度相同”**（例如判断 $a$ 和 $b$ 拼起来是不是等于 $n$ 拆开的数字）。
    
- **💡 核心动作**：千万不要转字符串排序！直接开一个大小为 10 的“数字桶” `bkt[10]`。自己人加钱（`+1`），敌人扣钱（`-1`）。最后查账，只要全是 0 就完美匹配！
    
- **💻 进阶 C++ 模板**：
    
    
    
    ```C++
    // 高级安检门：判断 a 和 b 的各位数字合起来，是不是和 n 一模一样
    bool check_anagram(int a, int b, int n)
    {
        // 💣 致命防爆零：账本必须每次查账时重新买新的（局部变量清零）！
        int bkt[10] = {0}; 
        int alen = 0, blen = 0, nlen = 0; // 长度校验器
    
        // 1. 剥洋葱进货（加钱）
        while(a > 0) { bkt[a % 10]++; alen++; a /= 10; }
        while(b > 0) { bkt[b % 10]++; blen++; b /= 10; }
    
        // 2. 剥洋葱销账（扣钱）
        while(n > 0) { bkt[n % 10]--; nlen++; n /= 10; }
    
        // 3. 极速安检
        if(alen + blen != nlen) return false; // 长度不对，直接枪毙
        for(int i = 0; i < 10; ++i) {
            if(bkt[i] != 0) return false; // 账本没平，说明数字对不上，枪毙
        }
        return true; // 完美匹配！
    }
    ```
    

### 🧠 防爆零终极心法口诀（血泪教训）：

1. **坚决不套娃**：不管题目让你找多长的数字串，永远只用一个 `while(x > 0)`。
    
2. **永远切原数**：砍位的永远是 `x /= 10`，绝对不能去切刚切下来的 `rem`。
    
3. **区分局部与全局**：**用来查账的 `bkt` 必须放局部每次清零！用来记录历史去重的 `vis` 必须放全局一直有效！** 混淆必死循环！
