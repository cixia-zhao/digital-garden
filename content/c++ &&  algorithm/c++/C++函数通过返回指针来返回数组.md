### 🧠 核心概念/问题
> C++的函数本身不能直接把一个数组作为返回值。那么，如果我需要一个函数创建并返回一个数组，应该如何实现？

### 💡 我的思考与解决方案
核心是利用**堆内存**和**指针**。函数内部的普通变量（在栈上）会在函数结束后被销毁，所以不能返回它们的地址。但通过`new`关键字在堆上创建的内存，其生命周期与函数无关，直到我们手动`delete`它才会释放。函数只需要返回指向这块堆内存的指针（地址）即可。

这个过程就像点外卖：函数（厨房）在公共取餐区（堆）做好了一份饭，然后不返回饭本身，而是返回一个取餐号（指针）。调用者（我）根据这个取餐号就能拿到饭。

#### 错误尝试 (如果适用)
我一开始会以为可以直接在函数里创建一个数组然后 `return` 它，像这样：
```cpp
// 错误示范！
int* getArr_wrong() {
    int localArr[5] = {0, 1, 2, 3, 4};
    return localArr; // 严重错误！
}
```
`localArr`是在**栈**上创建的，函数一结束，这个数组占用的内存就会被系统回收。返回它的地址就像给了别人一个已经作废的地址，再去访问就是访问非法内存，导致程序崩溃或未知行为（悬垂指针）。

#### 正确路径 / 关键代码
正确的做法是在函数内，使用`new`在**堆**上申请一块内存来存放数组。然后返回指向这块内存的指针。
```cpp
// 正确的关键代码
int* getArr() {
    // 1. 使用 new 在堆上申请一块可以存放5个int的内存
    int* arr = new int[5];

    // 2. 对这块内存进行操作（赋值）
    for (int i = 0; i < 5; ++i) {
        arr[i] = i;
    }

    // 3. 返回这块内存的首地址（指针）
    return arr;
}

int main() {
    // 接收从函数返回的、指向堆内存的指针
    int* myArray = getArr();

    // 通过指针可以安全地使用这块内存
    for (int i = 0; i < 5; ++i) {
        // ... 使用 myArray[i] ...
    }

    // 重要：堆内存需要手动释放，防止内存泄漏
    delete[] myArray;
    myArray = nullptr; // 好习惯：释放后将指针置空

    return 0;
}
```
