## 动态内存分配核心：malloc 与 free

### 核心速记

* **本质目的**：在程序运行期间，根据实际需求向操作系统**动态申请堆内存**（Heap），并在使用完毕后手动归还，避免栈空间溢出与内存浪费。
* **标准头文件**：`#include <stdlib.h>`
* **函数原型与基本语法**：
  * `void* malloc(size_t size)`：传入需要的字节数，返回指向该内存块首地址的通用指针 `void*`。
  * `void free(void *ptr)`：释放由 `malloc` 分配的内存，必须传入**申请时获得的原首地址**。
* **标准调用规范**：
  ```c
  #include <stdio.h>
  #include <stdlib.h>

  int main(void) {
      int number;
      scanf("%d", &number);

      // 1. 向堆区申请 number 个 int 大小的内存空间
      int *a = (int*)malloc(number * sizeof(int));

      // 2. 拿到指针后，可直接视作普通数组使用
      for (int i = 0; i < number; i++) {
          a[i] = i;
      }

      // 3. 有借有还，使用完毕必须释放
      free(a);
      return 0;
  }
  ```

> [!note]- 模糊点解析：指针指向已有变量 vs malloc 动态申请内存
> 
> * **指向已有变量（如 `int a; int *p = &a;`）**：
>   * 内存由编译器在**栈区**自动分配，生命周期受限于所在作用域（函数结束即销毁）。
>   * 无法在运行期动态扩容，也不能凭空对未初始化的野指针（如 `int *p; *p = 5;`）进行赋值。
> 
> * **动态申请内存（`malloc`）**：
>   * 内存由程序员向操作系统**堆区**申请，生命周期由程序员完全掌控（直到显式调用 `free`）。
>   * 是实现链表、树、图等**数据结构动态节点增删**的唯一底层手段。

## 内存申请极限与常见风险避坑

### 核心速记

* **申请失败处理**：当系统无足够连续内存时，`malloc` 会返回 `NULL`（即 `0`）。
* **NULL 与 free 的安全特性**：
  * 指针定义时建议默认初始化为 `NULL`（`int *p = NULL;`）。
  * 对 `NULL` 执行 `free(NULL)` 是**完全安全且合法**的，不会导致程序报错。
* **内存泄漏（Memory Leak）**：只申请不释放，程序长期运行会逐步耗尽系统内存。

> [!note]- 深度避坑：动态内存分配的四大致命错误
> 
> **1. 释放非首地址指针**
> * 错误示例：对指针进行了移动（如 `p++`）后执行 `free(p)`。
> * 后果：破坏系统内存管理元数据，程序崩溃退出（Abort trap）。
> 
> **2. 重复释放（Double Free）**
> * 错误示例：对同一块内存连续调用两次 `free(p)`。
> * 后果：触发系统安全机制并强制终止程序。
> 
> **3. 释放局部/静态变量地址**
> * 错误示例：`int i; int *p = &i; free(p);`
> * 后果：`free` 只能用于释放通过 `malloc` 分配的堆内存，释放栈内存会导致崩溃。
> 
> **4. 悬挂指针（Dangling Pointer）与野指针**
> * 现象：`free(p)` 之后，指针 `p` 依然保存着原来的地址，此时访问 `*p` 属于非法操作。
> * 避坑金律：释放后立即将指针置空：
>   ```c
>   free(p);
>   p = NULL; // 养成良好的防悬挂习惯
>   ```
