## C 语言进阶：联合（Union）与内存共享机制

### 核心速记

* **本质定义**：`union`（联合/共用体）在语法表达上与 `struct`（结构体）类似，但其所有成员**共享同一块内存空间**。
* **内存占用**：`sizeof(union)` 的大小取决于其**最大成员的 `sizeof`**，而非所有成员大小之和。
* **使用特性**：
  * 同一时刻只有当前赋值的成员是真正有效的。
  * 修改一个成员会同步覆盖共享内存区，导致其他成员的数据被破坏。
  * 初始化时，默认只能对**第一个成员**进行初始化。
* **核心用途**：
  * **节省内存**：不同时出现的多个数据字段复用同一块空间。
  * **内存透视**：通过重叠的不同数据类型（如 `int` 与 `char[]`）访问相同内存，观察或提取底层的二进制字节（常用于文件二进制读写、硬件接口与网络协议拆包）。

## 联合体的定义与成员访问

### 核心速记

* **声明语法**：
  ```c
  union AnElt {
      int i;
      char c;
  } elt1, elt2;
  ```
* **成员访问**：与结构体保持一致，使用点运算符（如 `elt1.i` 或 `elt2.c`）。

> [!note]- 深度避坑：union 与 struct 的本质区别
> 
> * **struct（结构体）**：各个成员位于独立的内存区域，互不干扰，可同时保持有效值。
> * **union（联合体）**：所有成员的首地址完全重合，共享单一存储空间，改写一个成员即同步更改其他成员对应的内存位。

## 经典应用：内存字节透视与大小端模式（Endianness）

### 核心速记

* **应用代码：提取整数的底层存储字节**
  ```c
  #include <stdio.h>

  typedef union {
      int i;
      char ch[sizeof(int)];
  } CHI;

  int main(void) {
      CHI chi;
      chi.i = 1234; // 1234 的十六进制表示为 0x000004D2

      for (int i = 0; i < sizeof(int); i++) {
          printf("%02hhX ", chi.ch[i]);
      }
      printf("\n");
      return 0;
  }
  ```

* **运行结果分析（以 x86 架构 CPU 为例）**：
  * 输出结果为：`D2 04 00 00`
  * 十六进制数 `0x000004D2` 的低位字节为 `D2`，高位字节为 `00`。
  * 实际内存布局：`ch[0] = D2`，`ch[1] = 04`，`ch[2] = 00`，`ch[3] = 00`。

* **大小端模式（字节序）结论**：
  * **小端模式（Little-Endian）**：低位字节存放在低内存地址（x86 / x64 常见）。
  * **大端模式（Big-Endian）**：高位字节存放在低内存地址（网络传输字节序常见）。

> [!note]- 模糊点解析：格式化输出 `%02hhX` 避坑指南
> 
> 在通过 `char` 数组透视内存时，`printf` 格式控制串 `%02hhX` 的作用如下：
> 
> * **`hh`**：修饰符，指定参数按 `char` 类型处理，防止高位进行符号扩展。
> * **`2`**：控制输出至少占 2 个字符宽度。
> * **`0`**：前导补零，确保单字节数据（如 `4`）格式化输出为两位十六进制数 `04`。
> * **`X`**：表示以大写十六进制形式打印。
> 
> 利用联合体进行字节透视，是深入理解 C 语言底层数据存储和进行二进制读写操作的核心方法。

## 十进制 1234 转换为十六进制 00 00 04 D2 全流程解析

### 核心速记

* **为什么有 4 个字节（8 位十六进制数）**：
  * C 语言中 `int` 类型通常占用 **4 个字节（32 位二进制）**。
  * 内存的基本存储和管理单位是**字节（Byte）**，1 个字节 = 8 位二进制 = **2 位十六进制数**。
  * 因此，4 个字节的 `int` 在内存中必须要凑齐 **$4 \times 2 = 8$ 位十六进制数**。
* **为什么 4D2 变成了 04D2**：
  * 手算得到的 `4D2` 只有 3 位十六进制数（即 12 位二进制）。
  * 从右往左划分字节：`D2` 刚好占满低位第 1 个字节；高位的 `4` 只有半个字节（4 位），必须在左边补 `0` 凑成 `04` 占满第 2 个字节。
* **完整 32 位表示**：低位两个字节为 `04 D2`，高位两个字节全为 `00`，组合起来就是 `00 00 04 D2`。
* **小端序（Little-Endian）倒转输出**：内存由低地址到高地址依次存放这 4 个字节：`D2 04 00 00`。

### 内存分布与字节对齐示意

```c
// 1234 (10进制) = 00000000 00000000 00000100 11010010 (2进制)

字节划分:     [高字节 4]  [高字节 3]  [高字节 2]  [低字节 1]
十六进制:        00          00          04          D2
内存地址:      高地址 <----------------------------> 低地址

小端序内存实际输出: D2 04 00 00 (按字节地址从低到高逐个读取)
```

> [!note]- 模糊点解析：如何精准判断何时补零与补几个零？
> 
> **1. 规则一：按“字节 (Byte)”对齐（1 字节 = 2 位十六进制）**
> * 计算机内存无法直接存半个字节。
> * 4 位二进制对应 1 位十六进制。因此，**1 个字节（8 位二进制）必须用 2 位十六进制数完整表示**。
> * 当你算出 `1234` 的十六进制是 `4D2` 时：
>   * 最右边的 `D2` 刚好是 2 位十六进制（1 个字节）。
>   * 剩下的 `4` 只有 1 位十六进制（半个字节），不能单独存放，必须在前面补 `0` 凑齐 2 位，变成 `04`。
> 
> **2. 规则二：按“数据类型 (Data Type)”的大小补齐**
> * 决定前面还要补几个 `00` 的，是变量的**数据类型**：
>   * 如果变量是 `short`（2 字节）：写满 4 位十六进制，即 `04 D2`。
>   * 如果变量是 `int`（4 字节）：写满 8 位十六进制，即 `00 00 04 D2`。
>   * 如果变量是 `long long`（8 字节）：写满 16 位十六进制，即 `00 00 00 00 00 00 04 D2`。
> 
> **总结三步判定口诀**：
> 1. **算数值**：手算十六进制得到 `4D2`。
> 2. **凑字节**：从右往左每 2 位补齐为一个字节 $\rightarrow$ `D2` 和 `04`。
> 3. **看类型**：`int` 是 4 字节，左边高位补足两个 `00` $\rightarrow$ 最终为 `00 00 04 D2`。
