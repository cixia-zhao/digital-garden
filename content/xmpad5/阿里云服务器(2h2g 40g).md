## 一句话概览

这是一台长期在线的阿里云 ECS 虚拟机，同时承载两个独立用途：

- 个人算法开发环境：`code-server` 与 Ubuntu 原生 C++ 工具链；
- “今日航线”Web 服务：FastAPI、SQLite 自动备份与 Tailscale Funnel HTTPS 入口。

服务器当前运行正常、负载很低。两个 Web 服务均只监听本机回环地址，不直接暴露业务端口；外部管理入口是 SSH，公网 Web 入口仅为 Tailscale Funnel。

## 3. 网络暴露面与访问路径

| 地址与端口 | 进程 | 含义 |
|---|---|---|
| `0.0.0.0:22`、`[::]:22` | `sshd` | SSH 管理入口 |
| `127.0.0.1:8080` | `node` / code-server | 仅本机可访问的算法开发环境 |
| `127.0.0.1:8000` | `python` / 今日航线 | 仅本机可访问的应用后端 |
| `100.65.244.77:443` | `tailscaled` | Tailscale Funnel HTTPS 接入点 |
| `127.0.0.53:53`、`127.0.0.54:53` | `systemd-resolved` | 本机 DNS stub resolver |

### Tailscale Funnel

- Tailscale 版本：`1.98.8`。
- 当前 Funnel：`https://daily-plan-aliyun.tail095eb1.ts.net`。
- 路由：`/` → `http://127.0.0.1:8000`。
- 该入口仅服务“今日航线”，不是通用反向代理，也不会暴露 code-server。
- `daily-plan-dns.service` 已将 `eth0` DNS 设为 `223.5.5.5` 与 `1.1.1.1`，用于保证 Funnel 证书续期链路。

### 防火墙与访问提醒

- 服务器内 UFW 当前为 `inactive`；`fail2ban` 未安装。
- SSH 的外层限制应依赖阿里云安全组；本次未读取阿里云控制台，安全组规则未核验。
- 不要把 `8000` 或 `8080` 直接开放到公网。
- 本机本次直连 TCP 22 超时，但通过本地 SOCKS5 代理 `127.0.0.1:7897` 可以 SSH 登录。这是当前客户端网络路径现象，不代表服务器 SSH 服务异常。

## 6. 维护红线

- 不要把 `8000` 或 `8080` 改为监听 `0.0.0.0`，也不要在安全组直接开放它们。
- 不要把 `/etc/daily-plan/daily-plan.env`、code-server 配置或任何密码、哈希、会话密钥写入笔记、截图、Git 或聊天记录。
- 不要直接复制正在写入的 SQLite 主库作为备份；今日航线继续使用项目提供的 SQLite backup API 备份脚本。
- 不要把 Funnel 当作通用公网入口；它当前只应代理 `127.0.0.1:8000`。
- 修改 systemd 服务文件后必须执行 `systemctl daemon-reload`，再检查服务和定时器状态。
- UFW 未启用不代表 SSH 已受限；调整网络规则时必须同时检查阿里云安全组。
